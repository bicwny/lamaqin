### **“修行记录 (Practice)” 模块 - 最终版开发指南**

**版本:** 1.2
**核心更新:** 增加了计时类修行项目在主页的“总时长”和“当期进度”的显示逻辑。

#### **一、 最终数据库结构**

1.  **`user_practice_projects` 表:** 新增 `target_period` 字段。

    ```sql
    CREATE TABLE public.user_practice_projects (
        -- ... (其他字段)
        daily_target integer DEFAULT 0, -- 对于计数类是每日目标遍数，对于计时类是每期目标座数
        target_period VARCHAR(10), -- 新增字段: 存储 'daily' 或 'weekly'
        start_date date,
        target_end_date date,
        -- ... (其他字段)
    );
    ```

2.  **`meditation_topics` 表:** 新增此表以存储观修方法。

    ```sql
    CREATE TABLE public.meditation_topics (
        id uuid NOT NULL DEFAULT gen_random_uuid(),
        practice_id uuid REFERENCES public.practices(id),
        topic_number integer NOT NULL,
        title character varying NOT NULL,
        description text,
        created_at timestamp with time zone DEFAULT now(),
        CONSTRAINT meditation_topics_pkey PRIMARY KEY (id)
    );
    ```

#### **三、 最终用户流程与技术指令**

##### **场景一：添加一个独立的修行项目 (流程不变)**

用户通过“添加修法”菜单，根据所选修法的类型（`count`或`time`），填写一个动态的目标设置表单。后端根据这些输入计算并创建一个新的 `user_practice_projects` 记录。

##### **场景二：查看修行主页（包含更新后的显示逻辑）**

这是本次更新的核心。

1.  **用户操作：** 进入或刷新“修行”主页。

2.  **界面呈现与UI故事板 (UI Presentation & Storyboard):**

    > **屏幕: 修行主页 (最终版显示逻辑)**

    > ```
    > 📿 修行记录
    > ```

    > 今日功课：
    > ┌─────────────────────────────┐
    > │ 顶礼：108/100000 ☐           │  \<-- 计数类
    > │ (每日目标: 1000遍)             │
    > ├─────────────────────────────┤
    > │ 前行观修(周)：34周 ☐         │  \<-- 每周计时类
    > │ (本周：1/5)                    │
    > │ [自定义记录]                   │
    > ├─────────────────────────────┤
    > │ 前行观修(日)：100天 ☐          │  \<-- 每日计时类
    > │ (今天：1座)                    │
    > │ [自定义记录]                   │
    > └─────────────────────────────┘
    > ...

    > ```
    > ```

3.  **前端显示逻辑详解:**
    当渲染“今日功课”列表时，前端需要对每一个修行项目执行以下判断和计算：

      * **如果项目是“计数类” (`type` = 'count'):**

          * 第一行显示：`[current_count]/[target_count]`。
          * 第二行显示：`(每日目标: [daily_target]遍)`。

      * **如果项目是“计时类” (`type` = 'time') 且 `target_period` = 'weekly':**

          * **第一行 (总时长):**
              * 计算 `总周数 = Math.ceil( (target_end_date - start_date) / 7 )`。
              * 显示为 `[总周数]周`。
          * **第二行 (本周进度):**
              * `Y` (周目标) = `daily_target`。
              * `X` (本周已完成) = 需要**执行一次数据库查询**：
                ```sql
                SELECT COUNT(*) FROM meditation_records
                WHERE user_id = ... AND practice_id = ...
                AND duration_minutes >= 15
                AND record_date BETWEEN '[本周一]' AND '[本周日]';
                ```
              * 显示为 `(本周：X/Y)`。

      * **如果项目是“计时类” (`type` = 'time') 且 `target_period` = 'daily':**

          * **第一行 (总时长):**
              * 计算 `总天数 = target_end_date - start_date`。
              * 显示为 `[总天数]天`。
          * **第二行 (今日进度):**
              * `X` (今日已完成) = 需要**执行一次数据库查询**：
                ```sql
                SELECT COUNT(*) FROM meditation_records
                WHERE user_id = ... AND practice_id = ...
                AND duration_minutes >= 15
                AND record_date = 'today';
                ```
              * 显示为 `(今天：X座)`。

##### **场景三：记录修行（流程不变）**

  * **计数类:** 用户输入完成的**遍数**。后端`INSERT`到`daily_records`，并`UPDATE` `user_practice_projects`的`current_count`。
  * **计时类:** 用户输入观修的**分钟数**。后端`INSERT`到`meditation_records`。总进度`current_count`的更新依赖于一个独立的计算任务（如上文SQL所示），而不是在记录时直接累加。
