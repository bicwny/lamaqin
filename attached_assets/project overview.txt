#### **2. 认证上下文设置**

```typescript
// components/auth/AuthProvider.tsx
import React, { createContext, useContext, useEffect, useState } from 'react';
import { Session, User } from '@supabase/supabase-js';
import { supabase } from '@/lib/supabase';

interface AuthContextType {
  user: User | null;
  session: Session | null;
  loading: boolean;
  signOut: () => Promise<void>;
}

const AuthContext = createContext<AuthContextType>({} as AuthContextType);

export function AuthProvider({ children }: { children: React.ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  const [session, setSession] = useState<Session | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // 获取初始会话
    supabase.auth.getSession().then(({ data: { session } }) => {
      setSession(session);
      setUser(session?.user ?? null);
      setLoading(false);
    });

    // 监听认证状态变化
    const { data: { subscription } } = supabase.auth.onAuthStateChange(
      async (event, session) => {
        setSession(session);
        setUser(session?.user ?? null);
        
        // 🔥 关键：邮箱验证成功后创建users表记录
        if (event === 'SIGNED_IN' && session?.user?.email_confirmed_at) {
          await ensureUserRecord(session.user);
        }
        
        setLoading(false);
      }
    );

    return () => subscription.unsubscribe();
  }, []);

  // 确保users表有对应记录
  const ensureUserRecord = async (authUser: User) => {
    try {
      // 检查users表是否已有记录
      const { data: existingUser, error: fetchError } = await supabase
        .from('users')
        .select('id')
        .eq('id', authUser.id)
        .single();

      if (fetchError && fetchError.code === 'PGRST116') {
        // 记录不存在，创建新记录
        const { error: insertError } = await supabase
          .from('users')
          .insert({
            id: authUser.id,
            email: authUser.email,
            // ✨ [更新] 从 user_metadata 中获取昵称
            display_name: authUser.user_metadata?.display_name || '新用户',
            created_at: new Date().toISOString(),
            updated_at: new Date().toISOString(),
          });

        if (insertError) {
          console.error('创建用户记录失败:', insertError);
        } else {
          console.log('用户记录创建成功');
        }
      }
    } catch (error) {
      console.error('检查用户记录失败:', error);
    }
  };

  const signOut = async () => {
    await supabase.auth.signOut();
  };

  return (
    <AuthContext.Provider value={{ user, session, loading, signOut }}>
      {children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth must be used within an AuthProvider');
  }
  return context;
};
```

### **📿 修行记录模块 (v2.0 - 全面更新)**

本模块采用高度动态和用户友好的设计，以下是完整的用户流程与开发指令。

#### **核心计算逻辑**

1.  **“有效座”的计算 (简化逻辑):**

      * **规则:** `meditation_records` 表中的**每一条记录都算作1个有效座**，与时长无关。
      * **SQL:** `SELECT COUNT(*) FROM meditation_records WHERE ...`

2.  **“总时长”的计算 (周/天):**

      * **总周数:** `Math.ceil( (target_end_date - start_date) / 7 )`
      * **总天数:** `target_end_date - start_date`

3.  **“当期进度”的计算 (本周/今天):**

      * **目标 (分母 Y):** 直接读取 `user_practice_projects.daily_target`。
      * **已完成 (分子 X):** 需要执行一次带日期范围的 `COUNT(*)` 查询。
          * **周:** `... WHERE record_date BETWEEN '[本周一]' AND '[本周日]'`
          * **天:** `... WHERE record_date = 'today'`

4.  **“当期详情”的生成:**

      * `SELECT duration_minutes FROM meditation_records WHERE ...` 查询当期的所有记录。
      * 遍历结果，按顺序生成 `第1座: XX分钟; 第2座: YY分钟;` 格式的字符串。

#### **流程A: 新用户首次进入**

  * **UI:** 显示空状态界面，含“开始您的修行之旅”和 `[添加修法]` 按钮。
  * **逻辑:** `SELECT count(*) FROM user_practice_projects`，若为0，则显示空状态。

#### **流程B: 添加一个独立的修行项目**

1.  **用户操作:** 点击`[添加修法]` -\> `[选择修法]` -\> 从列表中选择一个修法。
2.  **UI (条件分支):**
      * **若选择计数类修法:** 弹出表单，要求输入**总目标数量**和**计划时长**。
      * **若选择计时类修法:** 弹出表单，要求选择**修行频率**（每天/每周）、**每期座数**和**计划时长**。
3.  **后端逻辑:**
      * 接收前端数据，根据类型进行计算（每日目标遍数、总目标座数等）。
      * 在 `user_practice_projects` 表中创建一条新的修行项目记录。

#### **流程C: 查看修行主页**

  * **UI (动态显示):**

    > ```
    > 📿 修行记录
    > ```

    > ┌──────────────────────────┐
    > │ 顶礼 (计数类)              │
    > │ 108/100000 ☐             │
    > │ (每日目标: 1000遍)         │
    > │ [查看详情]      [记录]     │
    > ├──────────────────────────┤
    > │ 前行观修 (每周计时类)        │
    > │ 9周 ☐                    │
    > │ (本周：1/4) 第1座: 20分钟;   │
    > │ [查看详情]      [记录观修] │
    > └──────────────────────────┘

    > ```
    > ```

  * **前端逻辑:** 页面加载时，获取所有修行项目，并根据每个项目的类型（count/time）和周期（daily/weekly）**分别调用上述核心计算逻辑**，动态渲染出对应的卡片样式。

#### **流程D: 记录一次修行**

1.  **用户操作:** 点击项目卡片上的 `[记录]` 或 `[记录观修]` 按钮。
2.  **UI (简化弹窗):**
      * **计数类:** 弹窗只要求输入**完成的遍数**。
      * **计时类:** 弹窗只要求输入**观修的时长（分钟）**。
3.  **后端逻辑:**
      * **计数类:** `INSERT` 到 `daily_records`，并 `UPDATE` `user_practice_projects` 的 `current_count`。
      * **计时类:** `INSERT` 到 `meditation_records`。总进度的更新依赖于独立的“有效座”计算任务。

#### **流程E: 查看与编辑历史记录**

1.  **用户操作:** 点击项目卡片上的 `[查看详情]` 按钮。
2.  **UI:** 跳转到该项目的历史记录页面。
      * **布局:** 列表形式，最新记录在最上方。
      * **分页:** 初始加载12条，底部有 `[加载更多]` 按钮。
      * **操作:** 每条记录旁有 `[编辑]` 和 `[删除]` 按钮。
3.  **后端逻辑:**
      * **加载:** `SELECT ... ORDER BY record_date DESC, created_at DESC LIMIT 12 OFFSET [n]`
      * **编辑:** `UPDATE meditation_records SET duration_minutes = [新值] WHERE id = ...`
      * **删除:** `DELETE FROM meditation_records WHERE id = ...`
