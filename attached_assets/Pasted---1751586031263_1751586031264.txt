#### **二、 详细技术逻辑**

##### **1. 页面加载与数据获取逻辑 (屏幕 2)**

  * **前端逻辑:**
      * 页面加载时，向后端请求该修行项目（`practice_id`）的历史记录，并告知后端只需要第一页的数据（前12条）。
  * **后端及数据库逻辑:**
      * 执行一个带排序和分页的查询。
      * **SQL:**
        ```sql
        SELECT id, record_date, duration_minutes
        FROM public.meditation_records
        WHERE
            user_id = 'current_user_id'
            AND practice_id = 'qianxing_practice_id'
        -- 核心：按日期和创建时间倒序排列，确保最新记录在最上面
        ORDER BY record_date DESC, created_at DESC
        -- 初始加载12条
        LIMIT 12;
        ```

##### **2. “加载更多”逻辑 (屏幕 2)**

  * **前端逻辑:**
      * 前端需要维护一个“页码”或“偏移量”的状态。当用户点击 `[加载更多]` 时，请求下一页的数据（例如，第13到24条）。
      * 将新获取的数据追加到现有列表的末尾。
  * **后端及数据库逻辑:**
      * 在查询中使用 `OFFSET` 来跳过已经加载的记录。
      * **SQL (加载第二页):**
        ```sql
        SELECT ... FROM ... WHERE ... ORDER BY ...
        LIMIT 12
        OFFSET 12; -- 跳过前12条记录
        ```

##### **3. “编辑”功能逻辑 (屏幕 3)**

  * **前端逻辑:**
      * 当用户点击 `[编辑]` 时，打开“记录观修”弹窗组件。
      * 将该条记录的 `id` 和 `duration_minutes` 作为属性（props）传递给弹窗。
      * 弹窗内的输入框将 `duration_minutes` 作为其初始值。
      * 当用户点击 `[更新记录]` 时，将记录的 `id` 和新的分钟数发送给后端。
  * **后端及数据库逻辑:**
      * 执行 `UPDATE` 操作来更新指定的记录。
      * **SQL:**
        ```sql
        UPDATE public.meditation_records
        SET
            duration_minutes = [新的分钟数],
            updated_at = NOW() -- 更新修改时间
        WHERE
            id = '[要编辑的记录ID]' AND user_id = 'current_user_id';
        ```
      * **重要:** 操作成功后，需要通知前端刷新列表，以显示更新后的数据。

##### **4. “删除”功能逻辑 (建议补充)**

  * **前端逻辑:**
      * 点击 `[删除]` 后，弹出一个确认对话框：“您确定要删除这条记录吗？”
      * 用户确认后，向后端发送删除请求，并附上要删除记录的 `id`。
  * **后端及数据库逻辑:**
      * 执行 `DELETE` 操作。
      * **SQL:**
        ```sql
        DELETE FROM public.meditation_records
        WHERE id = '[要删除的记录ID]' AND user_id = 'current_user_id';
        ```
      * 操作成功后，通知前端将该条记录从列表中移除。
