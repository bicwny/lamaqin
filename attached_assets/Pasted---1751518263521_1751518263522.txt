### **“修行记录 (Practice)” 模块 - 超详细开发指南 (含UI故事板)**

本指南将按用户场景分解，详细说明每一步的界面、前端逻辑和后端数据库操作，为Replit Agent提供构建此模块所需的所有信息。

#### **场景一：新用户首次进入 (空状态)**

1.  **用户操作：** 用户在注册/登录后，首次点击底部导航栏的“修行”标签。

2.  **界面呈现与UI故事板 (UI Presentation & Storyboard):**

      * 系统应显示“空状态”界面，引导用户进行首次操作。

    > **屏幕 1: 修行主页 (空状态)**

    > ```
    > 📿 修行记录
    > ```

    > ┌─────────────────────────────┐
    > │                             │
    > │             📿             │
    > │                             │
    > │      开始您的修行之旅       │
    > │                             │
    > │  在这里追踪您的每日功课和    │
    > │  修行主题的完成进度。        │
    > │                             │
    > │        [ 添加修法 ]         │
    > │                             │
    > └─────────────────────────────┘

    > ```
    > ```

3.  **前端逻辑：**

      * 页面加载时，向后端请求当前用户的修行项目列表。
      * 通过查询 `user_practice_projects` 表，检查 `user_id` 为当前用户的记录数量。
      * 如果记录数为0，则渲染此“空状态”组件。

4.  **后端及数据库逻辑：**

      * `SELECT count(*) FROM user_practice_projects WHERE user_id = 'current_user_id';`
      * 返回查询结果（0）。

#### **场景二：用户添加第一个修行项目（加入主题）**

1.  **用户操作：** 在空状态页面，点击 `[添加修法]` 按钮。

2.  **界面呈现与UI故事板 (UI Presentation & Storyboard):**

      * **步骤A: 选择添加方式**
        系统提供一个清晰的菜单，让用户选择如何添加他的修行项目。

    > **屏幕 2: 添加修法功能 (弹窗)**

    > ```
    > ➕ 添加修法
    > ```

    > 选择添加方式：
    > ┌─────────────────────────────┐
    > │ 🎯 加入主题                  │
    > │ 选择预设的修行主题           │
    > │ [浏览主题]                  │  \<-- 用户点击这里
    > └─────────────────────────────┘
    > ... (其他选项)

    > ```
    > ```

      * **步骤B: 选择具体主题**
        用户点击`[浏览主题]`后，进入主题列表，选择一个系统性的主题。

    > **屏幕 3: 主题列表 (推断的界面)**

    > ```
    > 📚 浏览主题
    > ```

    > 选择您要加入的主题：
    > ┌─────────────────────────────┐
    > │ 📿 五加行                    │
    > │ 包含: 顶礼, 百字明, 发心...   │
    > │ [加入此主题]                │  \<-- 用户点击这里
    > └─────────────────────────────┘
    > ... (其他主题)

    > ```
    > ```

3.  **前端逻辑：**

      * 点击 `[浏览主题]` 后，向后端请求所有可用的修行主题，并渲染成列表。
      * 用户选择一个主题并确认后，向后端发送“加入主题”的请求，请求中包含所选主题的 `theme_id`。
      * 请求成功后，应自动导航回“修行主页”，此时主页会因为数据变化而重新渲染。

4.  **后端及数据库逻辑：**

      * **步骤 1: 查询主题包含的修法。**
          * `SELECT practice_id, target_count FROM theme_practices WHERE theme_id = 'selected_theme_id';`
      * **步骤 2: 为用户创建修行项目。**
          * 对于上一步查询到的**每一条**修法记录，都在 `user_practice_projects` 表中**插入一条新记录**。
          * `INSERT INTO user_practice_projects (user_id, theme_id, practice_id, target_count, status) VALUES ('current_user_id', 'selected_theme_id', 'practice_id_from_step1', 'target_count_from_step1', 'not_started');`

#### **场景四：记录一次“计数类”修行**

1.  **用户操作：** 在主页“今日功课”中，点击“顶礼”旁边的 `[自定义记录]` 按钮。

2.  **界面呈现与UI故事板 (UI Presentation & Storyboard):**

      * 弹出一个窗口，让用户输入他今天完成的数量。

    > **屏幕 5: 自定义记录 (弹窗)**

    > ```
    > 🙏 顶礼 - 自定义记录
    > ```

    > 当前进度：0次
    > ...

    > 输入完成数量：
    > [  108  ] 次  \<-- 用户输入

    > [确认] [取消]

    > ```
    > ```

3.  **用户操作（续）：** 输入 `108`，然后点击 `[确认]`。

4.  **前端逻辑：**

      * 点击`[确认]`后，将 `practice_project_id` 和用户输入的数量 `108` 发送给后端。
      * 在等待后端响应时，显示加载状态。
      * 接收到成功响应后，关闭弹窗，并**刷新主页的修行项目数据**，以便用户能立刻看到总进度更新。

5.  **后端及数据库逻辑 (这是一个事务，应保证两步都成功):**

      * **步骤 1: 记录每日流水。**
          * `INSERT INTO daily_records (user_id, practice_project_id, record_date, count) VALUES ('current_user_id', 'selected_project_id', 'current_date', 108);`
      * **步骤 2: 更新项目总进度。**
          * `UPDATE user_practice_projects SET current_count = current_count + 108, updated_at = NOW() WHERE id = 'selected_project_id';`
