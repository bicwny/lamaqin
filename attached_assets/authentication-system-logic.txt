
# AUTHENTICATION SYSTEM LOGIC - Buddhist Practice App

## OVERVIEW
This document outlines the complete authentication system architecture for the React Native Expo app "修行追踪" (Practice Tracking). The system uses Supabase as the backend authentication provider with email-based OTP (One-Time Password) verification for secure, passwordless authentication.

## 1. AUTHENTICATION ARCHITECTURE

### 1.1 Technology Stack
```
Frontend: React Native + Expo Router
Backend: Supabase (PostgreSQL + Auth)
Authentication Method: Email OTP (One-Time Password)
State Management: React Context API
Storage: AsyncStorage (React Native) / localStorage (Web)
Session Management: Supabase Auth with automatic token refresh
```

### 1.2 Core Components
```
📁 Authentication System
├── 🔐 Supabase Auth Service (lib/supabase.ts)
├── 🎯 AuthContext (contexts/AuthContext.tsx)
├── 📱 Auth Screens (app/auth/)
│   ├── unified.tsx (Smart unified flow)
│   ├── login.tsx (Login flow)
│   ├── register.tsx (Registration flow)
│   └── email-verification.tsx (Email verification)
├── 🛡️ Route Protection (_layout.tsx)
└── 💾 Session Persistence (AsyncStorage/localStorage)
```

## 2. AUTHENTICATION FLOW LOGIC

### 2.1 User Registration Flow
```
Registration Process:
1. User enters email + optional dharma_name
2. System calls supabase.auth.signInWithOtp() with shouldCreateUser: true
3. Supabase sends OTP to user's email
4. User enters OTP from email
5. System calls supabase.auth.verifyOtp()
6. On success: Create user record in database
7. Store session and redirect to main app

Technical Implementation:
┌─────────────────────────────────────────────────────────────┐
│ handleRegister() in register.tsx                            │
├─────────────────────────────────────────────────────────────┤
│ 1. Input Validation                                         │
│    - Check email format                                     │
│    - Check required fields                                  │
│                                                             │
│ 2. Send OTP (if not sent)                                   │
│    supabase.auth.signInWithOtp({                           │
│      email: email.trim(),                                   │
│      options: {                                             │
│        shouldCreateUser: true,                              │
│        data: { dharma_name: dharmaName.trim() || null }     │
│      }                                                      │
│    })                                                       │
│                                                             │
│ 3. Verify OTP (if sent)                                     │
│    supabase.auth.verifyOtp({                               │
│      email: email.trim(),                                   │
│      token: otp,                                            │
│      type: 'email'                                          │
│    })                                                       │
│                                                             │
│ 4. Update user metadata if dharma_name provided            │
│ 5. Redirect to /(tabs)/index                               │
└─────────────────────────────────────────────────────────────┘
```

## 3. SESSION MANAGEMENT

### 3.1 AuthContext Implementation
```
AuthContext Responsibilities:
1. Maintain global authentication state
2. Handle session persistence across app restarts
3. Manage automatic token refresh
4. Provide authentication methods to components
5. Handle logout and cleanup

State Structure:
interface AuthContextType {
  user: User | null;              // Current authenticated user
  loading: boolean;               // Loading state for auth operations
  signInWithOTP: (email: string) => Promise<{ error?: string }>;
  verifyOTP: (email: string, token: string) => Promise<{ error?: string }>;
  signUpWithOTP: (email: string, dharmaName?: string) => Promise<{ error?: string }>;
  signOut: () => Promise<void>;
  forceLogoutAll: () => Promise<void>;
  clearAllCache: () => Promise<void>;
}

User Object Structure:
interface User {
  id: string;                     // Supabase user ID
  email: string;                  // User's email address
  dharma_name?: string;           // Optional Buddhist dharma name
}
```

### 3.2 Session Persistence Logic
```
Multi-Platform Storage Strategy:
┌─────────────────────────────────────────────────────────────┐
│ createCustomStorage() in lib/supabase.ts                   │
├─────────────────────────────────────────────────────────────┤
│ Web Platform (Platform.OS === 'web'):                      │
│ ├── Primary: window.localStorage                           │
│ ├── Fallback: In-memory storage                            │
│ └── SSR Safe: Server-side rendering compatibility          │
│                                                             │
│ React Native Platform:                                      │
│ ├── Primary: AsyncStorage                                  │
│ ├── Secure: Expo SecureStore (when available)             │
│ └── Persistent: Survives app restarts                      │
│                                                             │
│ Storage Keys:                                               │
│ ├── 'sb-repl-auth-token' (Supabase session)               │
│ ├── '@user_session' (User data cache)                     │
│ └── '@auth_token' (Legacy support)                        │
└─────────────────────────────────────────────────────────────┘

Session Restoration Flow:
1. App starts → checkAuthState()
2. Try to get session from Supabase
3. If valid session exists → setUser() and continue
4. If no session → check AsyncStorage for cached data
5. If cached data valid → restore user state
6. If no valid data → redirect to auth screens
```

### 3.3 Automatic Token Refresh
```
Supabase Auth Configuration:
export const supabase = createClient(supabaseUrl, supabaseAnonKey, {
  auth: {
    storage: createCustomStorage(),     // Custom storage adapter
    autoRefreshToken: true,             // Auto-refresh expired tokens
    persistSession: true,               // Persist sessions
    detectSessionInUrl: Platform.OS === 'web', // Web URL detection
    flowType: 'pkce',                   // PKCE flow for security
    storageKey: 'sb-repl-auth-token',   // Custom storage key
    debug: false,                       // Production setting
  },
});

Token Refresh Events:
- TOKEN_REFRESHED: Successful token refresh
- INITIAL_SESSION: App startup session check
- SIGNED_IN: New authentication
- SIGNED_OUT: User logout
```

## 5. DATABASE INTEGRATION

### 5.1 User Creation Logic
```
Database User Creation:
┌─────────────────────────────────────────────────────────────┐
│ ensureUserInDatabase() in AuthContext                      │
├─────────────────────────────────────────────────────────────┤
│ 1. Health Check                                             │
│    - Test database connectivity                             │
│    - Verify table access permissions                       │
│                                                             │
│ 2. User Existence Check                                     │
│    SELECT id, email FROM users WHERE id = user.id          │
│                                                             │
│ 3. Create User if Not Exists                               │
│    INSERT INTO users (                                      │
│      id,                    // Supabase Auth user ID       │
│      email,                 // User's email address        │
│      dharma_name,           // Optional dharma name         │
│      created_at             // Timestamp                    │
│    )                                                        │
│                                                             │
│ 4. Error Handling                                           │
│    - Duplicate key errors (user created by another process)│
│    - Network connectivity issues                           │
│    - Database permission problems                          │
│    - Timeout handling (10 second limit)                   │
└─────────────────────────────────────────────────────────────┘

Database Schema:
CREATE TABLE users (
  id UUID PRIMARY KEY,              -- Matches Supabase auth.users.id
  email VARCHAR NOT NULL UNIQUE,    -- User's email address
  dharma_name VARCHAR,              -- Optional Buddhist name
  lay_name VARCHAR,                 -- Real name (required in profile)
  location VARCHAR,                 -- User's location
  class_name VARCHAR,               -- Buddhist class/group
  practice_years INTEGER,           -- Years of practice
  timezone_id VARCHAR,              -- User's timezone
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);
```

Required Profile Fields:

- dharma_name (法名): Buddhist name - OPTIONAL
- class_name (学修班级): Study group - OPTIONAL

```

## 6. SECURITY FEATURES

### 6.1 OTP Security
```
OTP Security Measures:
1. Time-based expiration (typically 5-10 minutes)
2. Single-use tokens (cannot be reused)
3. Rate limiting on OTP requests
4. Email delivery verification
5. Secure token generation by Supabase

Rate Limiting Logic:
- Maximum 3 OTP requests per 5 minutes per email
- Automatic backoff for repeated failures
- Countdown timer prevents spam requests
- Error tracking for security monitoring
```

### 6.2 Session Security
```
Session Security Features:
1. PKCE Flow (Proof Key for Code Exchange)
2. Automatic token refresh
3. Secure storage (encrypted on device)
4. Session invalidation on logout
5. Global logout capability

Storage Security:
- React Native: AsyncStorage (sandboxed per app)
  └── Enhanced: Expo SecureStore when available
- Web: localStorage (origin-isolated)
