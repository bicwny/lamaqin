
# Phase 4.3: Rollback Plan Documentation

## Overview
This document provides a systematic approach to reverting design system migration changes, handling dependencies, and implementing incremental testing strategies.

## 1. ROLLBACK STRATEGIES BY PHASE

### Phase 1: Auditing & Documentation (LOW RISK)
**What Was Done:**
- Created audit reports and documentation files
- No code changes to production files

**Rollback Strategy:**
```bash
# Simple file deletion - no dependencies
rm -rf attached_assets/1.1-style-inventory-comprehensive-report.txt
rm -rf attached_assets/1.2-typography-audit-*.txt
rm -rf attached_assets/1.3-color-usage-audit-results.txt
rm -rf attached_assets/1.4-spacing-pattern-analysis.txt
rm -rf attached_assets/1.5-component-pattern-documentation.txt
```

**Risk Level:** ⚠️ MINIMAL - Documentation only
**Dependencies:** None
**Testing Required:** None

---

### Phase 2: DesignSystem.ts Expansion (MEDIUM RISK)
**What Was Done:**
- Extended `constants/DesignSystem.ts` with new tokens
- Created utility files in `utils/` directory
- Added new color, spacing, and component tokens

**Rollback Strategy:**
```bash
# 1. Revert DesignSystem.ts to original state
git checkout HEAD~[number] -- constants/DesignSystem.ts

# 2. Remove utility files
rm utils/typography.ts
rm utils/colorMigration.ts
rm utils/spacingMigration.ts
rm utils/componentTokens.ts
rm utils/migrationTemplates.ts
rm utils/fileMigrationHelpers.ts

# 3. Check for any imports that need updating
grep -r "import.*typography" app/
grep -r "import.*colorMigration" app/
grep -r "import.*spacingMigration" app/
grep -r "import.*componentTokens" app/
```

**Risk Level:** ⚠️ MEDIUM - New utilities added
**Dependencies:** 
- Phase 3 migration templates depend on these utilities
- Any files that import these utilities will break

**Testing Required:**
- Run `npm run type-check` to verify no TypeScript errors
- Test that existing app functionality still works
- Verify no broken imports

---

### Phase 3: Migration Templates (MEDIUM RISK)
**What Was Done:**
- Created migration templates and helpers
- Built systematic transformation utilities
- No actual file migrations yet

**Rollback Strategy:**
```bash
# Remove migration template files
rm utils/migrationTemplates.ts
rm utils/fileMigrationHelpers.ts

# Remove template implementation reports
rm attached_assets/3.1-style-mapping-functions-implementation.txt

```

**Risk Level:** ⚠️ MEDIUM - Templates created but not applied
**Dependencies:**

**Testing Required:**

### Phase 4: File Migrations (HIGH RISK)
**What Was Done:**
- Applied migration templates to actual component files
- Updated imports from Colors.ts to DesignSystem.ts
- Replaced hardcoded values with design tokens

**Rollback Strategy:**
```bash

grep -r "ComponentTokens" app/ --include="*.tsx" --include="*.ts"

# 2. Revert specific files to pre-migration state
git checkout HEAD~[number] -- app/practice-detail/[practiceId].tsx
git checkout HEAD~[number] -- app/(tabs)/study.tsx
git checkout HEAD~[number] -- components/ModalTemplate.tsx
git checkout HEAD~[number] -- [other migrated files]

# 3. Restore original Colors.ts usage
# (This step depends on specific files migrated)
```

**Risk Level:** 🚨 HIGH - Production code changes
**Dependencies:** 
- Files depend on Phase 2 utilities
- Must revert Phase 2 utilities after file rollback

**Testing Required:**
- Full regression testing of all affected screens
- Visual comparison testing
- Performance testing
- User acceptance testing

```
Phase 4 (File Migrations) ←----/
```

```
Phase 4 (File Migrations) - ROLLBACK FIRST
    ↓
Phase 3 (Templates) - ROLLBACK SECOND
    ↓
Phase 2 (DesignSystem.ts) - ROLLBACK THIRD
    ↓
```

2. **Phase 4 → Phase 2**: Files using `Typography` need `typography.ts`

## 4. EMERGENCY ROLLBACK PROCEDURES

### Immediate Rollback (Critical Issues)
```bash
# 1. Stop the development server
# Ctrl+C or kill the process

# 2. Quick revert to last known good state
git stash  # Save any uncommitted changes
git checkout HEAD~[number]  # Go back to pre-migration commit

# 3. Restart and validate
npm run dev
```

### Selective Rollback (Specific Files)
```bash
# 1. Identify problematic files
# Check console errors and visual issues

# 2. Revert specific files
git checkout HEAD~[number] -- path/to/problematic/file.tsx

# 3. Test incrementally
npm run dev
# Test the specific functionality
```

### Partial Rollback (Keep Some Changes)
```bash
# 1. Create a branch for current state
git branch rollback-backup

# 2. Revert to earlier state
git checkout HEAD~[number]

# 3. Selectively apply good changes
git cherry-pick [commit-hash]  # Apply specific good commits

# 4. Test and validate
npm run dev
```

## 5. VALIDATION SCRIPTS

### Automated Rollback Validation
```bash
#!/bin/bash
# rollback-validator.sh

echo "🔄 Starting rollback validation..."

# Check TypeScript
echo "📝 Checking TypeScript..."
npm run type-check
if [ $? -ne 0 ]; then
    echo "❌ TypeScript errors found"
    exit 1
fi

# Check build
echo "🏗️ Testing build..."
npm run build
if [ $? -ne 0 ]; then
    echo "❌ Build failed"
    exit 1
fi

# Check for broken imports
echo "🔍 Checking for broken imports..."
grep -r "import.*componentTokens" app/ components/ 2>/dev/null
if [ $? -eq 0 ]; then
    echo "❌ Found references to removed componentTokens"
    exit 1
fi

grep -r "import.*typography" app/ components/ 2>/dev/null
if [ $? -eq 0 ]; then
    echo "❌ Found references to removed typography utils"
    exit 1
fi

echo "✅ Rollback validation passed"
```
