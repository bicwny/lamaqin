好的，我们来详细分解“计数类”修行（例如“百字明”、“顶礼”等）的完整逻辑。

它的核心是让用户可以非常灵活地设定目标（通过总数或每日量），并且系统能自动计算出相关的参考指标。

#### **第二部分：数据存储逻辑**

当用户点击“确认添加项目”后，后端会根据用户的输入模式，计算并存入一套完整的数据到`user_practice_projects`表中。

  * **情况A: 用户按“总数目标”设定**

      * **接收:** `total_count` (例如 100000) 和 `duration` (例如 180天)。
      * **计算:** `daily_target = Math.ceil(total_count / 180)`，结果为 `556`。
      * **存入数据库:** `target_count`存`100000`，`daily_target`存`556`。

  * **情况B: 用户按“每日目标”设定**

      * **接收:** `daily_target` (例如 500) 和 `duration` (例如 180天)。
      * **计算:** `total_count = daily_target * 180`，结果为 `90000`。
      * **存入数据库:** `target_count`存`90000`，`daily_target`存`500`。

**最终，`user_practice_projects` 表中的一条记录会包含完整的 `target_count` 和 `daily_target`。**

##### **技术逻辑**

这是一个**两步走的事务性操作**：

1.  **记录流水账:** 在`daily_records`表中插入一条新记录，记下今天的完成量。

      * **SQL:** `INSERT INTO daily_records (user_id, practice_project_id, record_date, count) VALUES ('...', '...', '2025-07-05', 600);`

2.  **更新总进度:** 在`user_practice_projects`表中，将总数累加上去。

      * **SQL:** `UPDATE user_practice_projects SET current_count = current_count + 600 WHERE id = '...';`

这个流程为计数类修行提供了一个从灵活设定目标，到简单记录，再到清晰反馈的完整闭环。
