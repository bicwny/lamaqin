
# Component Token Consolidation Plan
# Generated: January 15, 2025
# Analysis Based on: utils/componentTokens.ts and codebase investigation

## EXECUTIVE SUMMARY

Current State: 38 component variants across 7 categories
Target State: 18 consolidated components (53% reduction)
Risk Level: Medium (manageable with phased approach)
Timeline: 3-4 weeks with proper testing

## DETAILED CONSOLIDATION STRATEGY

### PHASE 1: LOW-RISK CONSOLIDATIONS (Week 1) (done)
Priority: High Impact, Low Risk

#### 1.1 Progress Component Consolidation
**Current:** 3 variants (bar, course, practice)
**Target:** 1 component with size prop

BEFORE:
- progress.bar (height: 8px)
- progress.course (height: 12px) 
- progress.practice (height: 10px)

AFTER:
- Single ProgressBar component
- Props: size={'thin'|'medium'|'thick'}
- Implementation: size maps to height values

**Impact Analysis:**
- Files Affected: 12 files use progress bars
- Risk Level: Very Low (isolated styling)
- Bundle Reduction: ~180 lines of duplicate code
- Breaking Changes: None (visual outcome identical)

#### 1.2 Header Component Consolidation
**Current:** 3 variants (page, modal, section)
**Target:** 1 component with context prop

BEFORE:
- header.page (border, padding: 16px)
- header.modal (border, padding: 16px)
- header.section (no border, padding: 8px)

AFTER:
- Single Header component
- Props: context={'page'|'modal'|'section'}
- Auto-applies appropriate styling

**Impact Analysis:**
- Files Affected: 28 header usages across app
- Risk Level: Low (contained styling differences)
- Bundle Reduction: ~150 lines of code
- Breaking Changes: None

#### 1.3 Buddhist-Specific Token Simplification
**Current:** 4 Buddhist variants (dharmaCard, meditationCard, wisdomBadge, completionBadge)
**Target:** Merge into semantic system

CONSOLIDATION:
- dharmaCard → card.standard + semantic.dharma color
- meditationCard → card.standard + semantic.meditation color
- wisdomBadge → badge.small + semantic.wisdom color
- completionBadge → badge.small + semantic.success color

**Impact Analysis:**
- Files Affected: 15 Buddhist-themed components
- Risk Level: Low (color-only changes)
- Bundle Reduction: ~200 lines of specialized code
- Breaking Changes: None (same visual output)

### PHASE 2: MEDIUM-RISK CONSOLIDATIONS (Week 2)

#### 2.1 Input Component Consolidation
**Current:** 3 variants (standard, search, textarea)
**Target:** 2 variants with props

BEFORE:
- input.standard (border, padding: 12px)
- input.search (different border, padding: 16px)
- input.textarea (multiline, height: 80px)

AFTER:
- input.outlined (replaces standard + search)
- input.filled (new variant)
- Props: multiline, size, variant

**Impact Analysis:**
- Files Affected: 45 input fields across app
- Risk Level: Medium (API changes required)
- Bundle Reduction: ~120 lines of duplicate styling
- Breaking Changes: Minimal (prop updates needed)

**Migration Strategy:**
1. Add new consolidated components
2. Update imports file by file
3. Remove old variants
4. Test form functionality

#### 2.2 Button Variant Consolidation
**Current:** 5 variants (primary, secondary, small, text, dharma)
**Target:** 3 variants with size prop

BEFORE:
- button.primary (red background)
- button.secondary (white + red border)
- button.small (smaller padding)
- button.text (transparent background)
- button.dharma (identical to primary)

AFTER:
- button.primary (solid style)
- button.secondary (outlined style)
- button.ghost (replaces text)
- Props: size={'small'|'medium'|'large'}

**Impact Analysis:**
- Files Affected: 156 button usages (most common component)
- Risk Level: Medium (high usage but well-contained)
- Bundle Reduction: ~300 lines of button definitions
- Breaking Changes: 'dharma' → 'primary', 'small' → size prop

**Migration Strategy:**
1. Create mapping utility: dharma → primary
2. Batch replace small buttons with size prop
3. Update all button imports systematically
4. Visual regression testing on each screen

### PHASE 3: HIGH-RISK CONSOLIDATIONS (Week 3)

#### 3.1 Card Component Consolidation
**Current:** 4 variants (standard, practice, course, status)
**Target:** 2 variants with padding prop

ANALYSIS OF DIFFERENCES:
- standard vs practice: Only padding differs (20px vs 16px)
- standard vs course: Only shadow differs (elevation 4 vs 6)
- status: Completely different (should be notification component)

CONSOLIDATION:
- card.elevated (high shadow, replaces course)
- card.outlined (low shadow, replaces standard + practice)
- Props: padding={'compact'|'comfortable'|'spacious'}
- Remove status → create separate Notification component

**Impact Analysis:**
- Files Affected: 89 card usages (critical component)
- Risk Level: High (affects core app layout)
- Bundle Reduction: ~400 lines of duplicate card styling
- Breaking Changes: status cards need component migration

**Migration Strategy:**
1. Week 3.1: Create new consolidated card components
2. Week 3.2: Migrate non-critical screens first
3. Week 3.3: Migrate status cards to notification component
4. Week 3.4: Update core screens (practice lists, course cards)
5. Extensive visual testing at each step

#### 3.2 Modal Component Consolidation
**Current:** 4 variants (standard, fullscreen, alert, overlay)
**Target:** 2 variants with size prop

BEFORE:
- modal.standard (padding: 20px, margin: 20px)
- modal.fullscreen (no padding/margin)
- modal.alert (padding: 32px, margin: 32px)
- modal.overlay (background only)

AFTER:
- modal.dialog (replaces standard + alert)
- modal.fullscreen (unchanged)
- Props: size={'compact'|'default'|'large'}
- overlay becomes separate utility

**Impact Analysis:**
- Files Affected: 34 modal usages
- Risk Level: High (affects navigation flow)
- Bundle Reduction: ~180 lines of modal definitions
- Breaking Changes: alert → dialog with size='compact'
